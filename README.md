# Textile Business Intelligence & Analytics Platform

An end-to-end analytics pipeline built around real workflows of a textile
trading business (sales, customer, and inventory data), built as a portfolio
project for **Durga Shirtings Private Limited** (CIN: U17120MH2009PTC197409),
a Mumbai-based textile company.

> ⚠️ **Data disclosure:** This repository ships with **synthetic data**
> (`data/raw/*.csv`) generated by `etl/generate_synthetic_data.py`. It
> structurally mirrors a textile trading business — fabric SKUs, meter-based
> units, wholesale/retail/export customer segments — but does **not**
> represent Durga Shirtings' actual customers, products, prices, or
> financials. Swap in real company exports matching these column headers to
> go live; no pipeline code needs to change. See `docs/` for details.

## Why this project exists

Most portfolio analytics projects are a Kaggle CSV and a dashboard. This one
is built the way a real internal BI system gets built: messy raw exports →
a Python ETL layer that validates and quarantines bad data with an audit
trail → a proper SQL star schema → analytical SQL views that do the actual
statistical work (Pareto, RFM segmentation, z-score anomaly detection) →
Tableau on top. Every design decision below is one I can defend in an
interview.

## Architecture

```
Raw CSV (synthetic, replaceable)
        │
        ▼
Python ETL  (etl/clean_and_load.py)
  - dedup, null/invalid checks, name standardization
  - every rejected row logged to dq_log with a reason
        │
        ▼
SQLite star schema  (sql/schema.sql)
  - dim_customer, dim_product, dim_date
  - fact_sales, fact_inventory_snapshot, dq_log
        │
        ▼
Analytical SQL views  (sql/analytical_views.sql)
  - v_monthly_sales, v_product_performance, v_customer_pareto,
    v_customer_rfm, v_inventory_status, v_order_anomalies, v_dq_summary
        │
        ▼
Tableau dashboards  (docs/tableau_dashboard_design.md)
  - Sales Overview / Customer Analytics / Inventory & Operations / Data Quality
```

## How to run it

```bash
pip install -r requirements.txt

cd etl
python generate_synthetic_data.py   # writes data/raw/*.csv
python clean_and_load.py            # cleans + loads data/clean/durga_shirtings.db
python forecast.py                  # writes data/clean/forecast_output.csv

# then load sql/analytical_views.sql into the same db (clean_and_load.py
# already does this on first run) and point Tableau at data/clean/durga_shirtings.db
```

## Generate Tableau-ready extracts (recommended)

From the repository root:

```bash
pip install -r requirements.txt
python etl/prepare_tableau_assets.py
```

This command creates/refreshes assets in:

- `data/clean/durga_shirtings.db` (if missing)
- `data/clean/forecast_output.csv` (if missing or ETL was refreshed)
- `data/clean/tableau_extracts/*.csv` (dashboard-ready extracts)

Useful flags:

```bash
python etl/prepare_tableau_assets.py --force-etl --force-forecast
```

### Connect Tableau

Use either approach:

1. **CSV extracts (no SQLite connector needed):** connect Tableau to files in
   `data/clean/tableau_extracts/`.
2. **SQLite live source:** connect Tableau to
   `data/clean/durga_shirtings.db` and use the analytical views.

The dashboard-by-dashboard file mapping and required fields are documented in
`docs/tableau_dashboard_design.md`.

## What each layer demonstrates

| Layer | Skills shown |
|---|---|
| `generate_synthetic_data.py` | Realistic data simulation, deliberate injection of known data-quality problems |
| `clean_and_load.py` | Python/Pandas data validation, referential integrity checks, audit logging, ETL design |
| `schema.sql` | Relational modeling (star schema), indexing for query performance |
| `analytical_views.sql` | Window functions (running totals, NTILE, LAG), Pareto analysis, RFM segmentation, z-score anomaly detection |
| `forecast.py` | Basic statistical forecasting, honest model evaluation (reporting R² rather than hiding a poor fit) |
| Tableau dashboards | Data viz design, KPI communication, filter/interaction design |

## Swapping in real company data

Replace the four files in `data/raw/` with real exports using the same
column headers (see `docs/` for the exact schema each file needs). Re-run
`clean_and_load.py` — the pipeline, schema, views, and dashboards all stay
the same.
